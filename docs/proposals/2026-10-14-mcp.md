# Proposal: extract `craft-mcp` — the MCP JSON-RPC client/server boundary

- **Proposed crate:** `crates/mcp`, package `craft-mcp` (crate naming
  per target AGENTS.md; registered in `[workspace.dependencies]`).
- **Window:** 7h look-back ending 2026-10-14 02:51 UTC.
- **Status:** evidence proposal only — no code is extracted in this
  phase. Humans decide; this document carries the evidence.

## Why (duplication + drift signal)

The MCP client/server surface is duplicated across the Craft suite:
`mcp` appears as a known shared-crate candidate in the adoption scan
list for `storytold/vectorcraft`, `storytold/deckcraft`,
`storytold/gridcraft` and `storytold/wordcraft`, and `crates/mcp` is a
watch-path in three of them. This window produced three independent
merged fixes to vectorcraft's copy — all generic transport/protocol
hardening, none touching vectorcraft's document model:

1. **[vectorcraft#1739](https://github.com/storytold/vectorcraft/pull/1739)**
   — "MCP: reconnect closed control sockets before sending requests"
   (merged 2026-10-14 01:09 UTC window). The client sends a request on
   a socket the app has already closed and fails every call until
   reset. Fix: probe the cached connection with a non-blocking
   `TcpStream::peek` before each call and reconnect on stale sockets
   (crates/mcp/src/backend.rs, +26/−1).
2. **[vectorcraft#1768](https://github.com/storytold/vectorcraft/pull/1768)**
   — "Fix #1728: require the JSON-RPC 2.0 envelope and correlate
   control replies" (merged in window). The client ignored the `id`
   field, so replies could be paired with the wrong request.
   crates/mcp/src/backend.rs (+17), server.rs (+6), property tests in
   crates/mcp/tests/protocol_props.rs (+64).
3. **[vectorcraft#1764](https://github.com/storytold/vectorcraft/pull/1764)**
   — "Fix #1727: cap MCP framing input, batches and kept
   command_batch results" (merged in window). Unbounded framing,
   batch and retained-result sizes let a runaway client exhaust
   memory; caps were added in crates/mcp/src/server.rs (+79/−7) and
   tools.rs (+28/−4) with 174 lines of limit tests
   (crates/mcp/src/tests_limits.rs).

Any suite app that speaks MCP to its engine hits the same three
failure modes: stale sockets, uncorrelated replies, unbounded input.
The fixes landed in vectorcraft's copy; the other MCP-listed apps
(deckcraft, gridcraft, wordcraft) still carry the older behavior.

## File inventory (from the evidence merges)

- `crates/mcp/src/backend.rs` — client `Remote`: connection cache,
  stale-socket probe (#1739), reply id correlation (#1768).
- `crates/mcp/src/server.rs` — framing/batch/retention caps (#1764),
  envelope validation (#1768).
- `crates/mcp/src/tools.rs` — command_batch result retention caps
  (#1764).
- `crates/mcp/src/lib.rs` — limit re-exports (#1764).
- Tests: `tests.rs`, `tests_protocol.rs`, `tests_limits.rs`,
  `tests/protocol_props.rs` — +417 lines across the three merges.
- Docs: `docs/mcp.md` updated by all three merges.

## Proposed extraction shape (for the humans, not done here)

- `craft-mcp::client` — the `Remote` backend with `prepare_connection`
  stale-socket probing (#1739) and request-id reply correlation
  (#1768); apps name their endpoint, the transport stays shared.
- `craft-mcp::server` — JSON-RPC 2.0 envelope enforcement, reply
  correlation and framing/batch caps (#1764, #1768) with the limit
  knobs as configuration, not app constants.
- App-specific tool catalogs and document commands stay in each app
  (vectorcraft's tools.rs command surface is app-domain and does not
  move).

## Architecture compliance (target AGENTS.md)

- `craft-mcp` would be useful to more than one app (four suite apps
  list MCP as a candidate) and depends on no app — the client/server
  boundary is app-agnostic; app tool catalogs stay per-app.
- Standards to uphold at extraction time: the never-crash deny set
  (`unwrap_used`, `expect_used`, `panic`, …) — note #1739's test probe
  uses `unwrap` under `#[cfg(test)]`, acceptable, but the extracted
  crate body must not; no `unsafe`; gates `cargo fmt --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`.
- Scope: this is a protocol transport, not a universal renderer, not
  i18n, not fonts — within target scope policy.
