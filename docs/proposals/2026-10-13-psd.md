# Proposal: `craft-psd` — shared PSD decode/export robustness

**Window:** 2026-10-13, 7-hour look-back (2026-10-13T13:33:58Z – 20:33:58Z).
**Status:** evidence-only proposal. No code is extracted in this phase; humans decide.
**Target crate:** `craft-psd` (new crate under `crates/psd`, named per the
`craft-<name>` convention), carrying PSD parsing, merged-image channel access
and section-divider allocation, independent of any app's document model.

## Why a shared crate

Five merges in this single window — four of them by three different
authors — harden or extend PSD handling in `storytold/photocraft`'s
`crates/psd` and `crates/io`. PSD is a suite-wide interchange format: the
adoption scan's repo list names `psd`/`io`/`codecs` as shared-crate candidates
across the suite (photocraft, deckcraft, filmcraft), and
`storytold/deckcraft#317` has already vendored a sibling crate (wordcraft's
`metafile`) rather than wait for a shared one. Every fix below reads like a
fix any other Craft app that opens PSD files would want unchanged.

The failing patterns are the ones [craftrules](https://github.com/storytold/craftrules)
`never-crash.md` exists for: unchecked slice arithmetic, unchecked integer
overflow on attacker/corrupt-file-controlled sizes, and decode-order bugs
where work happens before validation.

## Evidence (merged pull requests)

All five merged inside this run's window (2026-10-13, 15:56–17:24 UTC).

### storytold/photocraft#4994 — Validate merged PSD channel indices before decoding
- **Author:** Ni-zav, merged 2026-10-13T15:56:48Z, merge commit `40c9c3c451e7`.
- **Files:** `crates/psd/src/image_data.rs`.
- **What it does:** `ImageData::decode_channel` previously decoded the merged
  image before checking that the requested channel index existed, and computed
  the channel byte range with unchecked `index * plane` arithmetic — an
  overflow and a panic on corrupt/oversized inputs. Now: index bounds are
  rejected first, and the plane size, start and end are computed with
  `checked_mul`/`checked_add`, returning a typed `PsdError::invalid`.
- **Why generic:** bounds-check + checked arithmetic before decode; zero app
  vocabulary. Regression tests cover valid channels, the first out-of-range
  index, `usize::MAX` and corrupt merged data.

### storytold/photocraft#4885 — fix(psd): reserve imported layer IDs when allocating section dividers
- **Author:** Ni-zav, merged 2026-10-13T15:56:55Z, merge commit `ccb33741f9dc`.
- **Files:** `crates/io/src/psd_export.rs`.
- **What it does:** the PSD exporter generated section-divider IDs by
  incrementing the highest imported layer ID without an overflow or
  collision check. Now: imported layer IDs are tracked in a reserved set and
  generated IDs are allocated with wrapping arithmetic that skips IDs already
  in use, so a group with an imported `u32::MAX` ID round-trips.
- **Why generic:** allocator correctness (collision-free, overflow-safe ID
  generation) is exactly the class of bug every app's PSD exporter carries.

### storytold/photocraft#4950 — fix(psd): prioritize 16-bit and 32-bit global layer blocks over compatibility section
- **Author:** Sir-Starch, merged 2026-10-13T16:56:16Z, merge commit `3260f6abb974`.
- **Files:** `crates/psd/src/file.rs`, `crates/io/tests/roundtrip.rs`.
- **What it does:** for 16-bit documents Photoshop stores the real layer
  records in the global `Lr16`/`Lr32` tagged block while the classic Layer
  Info section holds only a compatibility copy. The decoder now selects the
  authoritative section by bit depth, so multi-layer 16-bit files no longer
  open with their layers hidden behind a synthesized background.
- **Why generic:** a decode-order/precedence rule of the PSD container itself;
  any app opening 16-bit PSDs hits the same silent wrong-layers bug.

### storytold/photocraft#3560 — PSD: Backgrounds survive a round trip through PhotoCraft
- **Author:** MrCloudy2, merged 2026-10-13T16:56:08Z, merge commit `57624bd02eae`.
- **Files:** `crates/io/src/psd_export.rs`, `crates/io/src/psd_import.rs`.
- **What it does:** round-trip fidelity for PSD background layers.
- **Why generic:** round-trip correctness of a shared container format; same
  contract any suite app's PSD path needs.

### storytold/photocraft#2754 — PSD: parallel RLE for the merged image
- **Author:** Elvis33LE, merged 2026-10-13T17:23:45Z, merge commit `fc0a579a4acd`.
- **Files:** `crates/psd/src/compression.rs`, `crates/io/src/psd_export.rs`,
  `crates/io/src/psd_import.rs`, `crates/io/tests/psd_roundtrip_bytes.rs`.
- **What it does:** PSD RLE decode/encode runs on all cores; layer channels
  decode and gather in parallel.
- **Why generic:** the RLE packbits codec is pure container mechanics (and
  this same merge pattern was deferred as weak-hoist in the previous run's
  rollup for lack of corroboration; this window supplies the cluster).

## Scope of the proposed crate

Extract from `photocraft`'s `crates/psd` plus the PSD-specific parts of
`crates/io`: the file/header/section parser (`file.rs`, `image_data.rs`),
RLE compression (`compression.rs`), and section-divider ID allocation; the
app-side glue (document model, layer conversion) stays in the app.

- `crates/psd` → `craft-psd`, `#![deny(clippy::unwrap_used,
  clippy::expect_used, clippy::panic, clippy::unimplemented, clippy::todo,
  clippy::unreachable)]` first line, no `unsafe`, no app dependencies
  (AGENTS.md).
- Listed in `[workspace.dependencies]`; consumed by apps as a pinned `rev`.
- Gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D
  warnings`, `cargo test --workspace`.
