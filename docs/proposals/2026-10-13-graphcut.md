# Proposal: `craft-graphcut` — shared segmentation / graph-cut liveness

**Window:** 2026-10-13, 7-hour look-back (2026-10-13T13:33:58Z – 20:33:58Z).
**Status:** evidence-only proposal. No code is extracted in this phase; humans decide.
**Target crate:** `craft-graphcut` (new crate under `crates/graphcut`, named
per the `craft-<name>` convention), carrying the segmentation algorithms —
graph-cut max-flow (push/relabel), GrabCut iteration, and subject-selection
band refinement — as a cancellable, never-crashing library without any
app's cutout vocabulary.

## Why a shared crate

Two merges in this window, by the same author, made the segmentation stack in
`storytold/photocraft`'s `crates/algo/src/segment` correct and responsive:
one fixed an unbounded push/relabel loop on unreachable nodes (a hang), the
other threaded cancellation through every graph cut so Cancel/Esc actually
stops a running selection. Both are library-lifecycle properties —
termination and cooperatively-cancellable long jobs — that any app embedding
segmentation inherits unchanged, and both were written as library code, not
app code.

## Evidence (merged pull requests)

### storytold/photocraft#4869 — fix(segment): stop push/relabel looping forever on unreachable nodes
- **Author:** LloydNicholson, merged 2026-10-13T15:56:35Z, merge commit `1735c81e67ca`.
- **Files:** `crates/algo/src/segment/maxflow/push_relabel.rs`,
  `crates/algo/src/segment/maxflow/push_relabel/tests.rs`.
- **What it does:** the push/relabel max-flow implementation looped forever
  when the graph contained unreachable nodes. The fix removes the
  non-termination with regression coverage; the same author's #4878 body
  cites it ("the push/relabel loop fixed in #4869").
- **Why generic:** a termination guarantee in a max-flow kernel is
  algorithm-correctness work with zero app vocabulary.

### storytold/photocraft#4878 — fix(segment): let Remove Background's cancel stop Select Subject's min cuts
- **Author:** LloydNicholson, merged 2026-10-13T16:56:22Z, merge commit `25a82978b21e`.
- **Files:** `crates/algo/src/segment/grabcut.rs`,
  `crates/algo/src/segment/mod.rs`, `crates/algo/src/segment/subject.rs`,
  `crates/algo/src/segment/tests.rs` (the `crates/engine` touch,
  `cutout_cmds.rs`, is app glue that stays behind).
- **What it does:** the subject-selection job checked cancellation only
  before and after `subject::select_subject`; inside, every graph cut ran
  through a non-cancellable `grid_cut`, so Cancel/Esc did nothing until the
  whole step finished. The change threads a cancellation callback through
  GrabCut iterations and the full-resolution band re-cut (tile set includes
  a rayon fan-out).
- **Why generic:** cooperative cancellation of long-running algorithm phases
  is a library contract. The app-only part is the mapping from a UI cancel
  to the callback; the threading through the algorithm belongs in a shared
  crate.

## Scope of the proposed crate

Extract `photocraft`'s `crates/algo/src/segment` (maxflow push/relabel,
GrabCut, subject band refinement) into `craft-graphcut`, taking a
cancellation callback as a parameter instead of the app's job context. The
`crates/engine` command glue (`cutout_cmds.rs`) and the "Remove Background"
feature surface stay in the app.

- `crates/graphcut` → `craft-graphcut`, never-crash lints per AGENTS.md,
  no `unsafe`, no app dependencies.
- Listed in `[workspace.dependencies]`; consumed by apps as a pinned `rev`.
- Gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D
  warnings`, `cargo test --workspace`.
