# Proposal: `craft-fontdb` — shared font discovery and font diagnostics

**Status:** proposal (evidence only; no code extraction in this phase — humans decide)
**Target crate name:** `craft-fontdb` (`crates/fontdb`, named per AGENTS.md)
**Date:** 2026-10-13

## Why

Font discovery is being rebuilt per app. In this window alone, two apps shipped overlapping
work and a third ships the PDF-metrics sibling:

- deckcraft#322 "Fonts: missing fonts draw as PowerPoint draws them, and Windows family names
  resolve" (merged 2026-10-12T23:05:49Z, merge commit `55a53f8ecb9d38a067cb79bc5f09b049fbe66a6f`)
  — `crates/fonts/src/fontdb.rs` +124/−11: Windows family-name resolution and compatibility
  aliases so a deck's Calibri resolves like PowerPoint's.
- deckcraft#326 "Fonts: use Office's downloaded fonts, and say which fonts a file is missing"
  (merged 2026-10-13T00:34:54Z, merge commit `85366b1a62478884c9c850975853e169aba2ff10`) —
  `crates/fonts/src/fontdb.rs` (+65), `crates/fonts/src/lib.rs` (+62), missing-font toast in
  `crates/ui-egui/src/toast.rs` (+94) plus engine wiring.
- vectorcraft#1548 "Fix #1529: Linux reads the font folders fontconfig is set up with"
  (merged 2026-10-13T00:14:31Z, merge commit `d9e44350d28cd79d660d49c9e0ce51dc747d0a6a`) —
  new `crates/text/src/fontconfig.rs` (+253) plus `crates/text/src/fontdb.rs` wiring.

Three apps independently maintain font discovery logic; the next app to need Office-alias
resolution or fontconfig scanning will copy one of these again. The changes are generic
(they read OS font folders and name tables; no deck/vector/document model), which is exactly
the "useful to more than one app, no app dependency" bar of the target's AGENTS.md.

## What the shared crate would own

- OS font folder enumeration (Windows fonts dir, Office-downloaded fonts, macOS, Linux
  `/usr/share/fonts`, XDG dirs, and the fontconfig `<dir>` set from
  `/etc/fonts/fonts.conf` + includes).
- Family-name resolution incl. Windows compatibility aliases (deckcraft#322 semantics).
- Missing-font diagnostics: the query surface deckcraft#326's toast consumes.

## What stays in each app

- Font *rendering*, shaping, fallback chains and app-specific font policies (already app-side).
- Presentation (deckcraft's toast widget lives in app UI; the shared crate only answers
  "which fonts is this file missing?").
- PDF standard-14 metrics (pdfcraft#357) — a different concern (embedding/metrics), not
  discovery; recorded for a future proposal, not part of this one.

## Architecture compliance (target AGENTS.md)

- Useful to more than one app: deckcraft, vectorcraft evidence above; pdfcraft's font work is
  adjacent. At least two apps is the AGENTS.md bar.
- No app code: discovery/diagnostics only; no document model, no engine, no UI dependency.
  Apps keep rendering and policy.
- New crate rules honored: `crates/fontdb`, name `craft-fontdb`, workspace-inherited package
  fields and lints, listed in `[workspace.dependencies]`, `#![deny(clippy::unwrap_used, …)]`
  header, no unsafe.
- Gate commands before merging: `cargo fmt --check`, `cargo clippy --workspace --all-targets
  -- -D warnings`, `cargo test --workspace`.
- Scope check: not a universal renderer (rendering stays app-side), not i18n, no font
  binaries bundled (discovery reads system fonts; no assets shipped).
