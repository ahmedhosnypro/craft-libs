## What the shared crate would own (unchanged boundary)

- OS font enumeration (Windows user/system + Office directories,
  fontconfig on Linux, macOS font directories), family grouping and
  style/weight/italic classification, name normalization and alias
  resolution.
- Face-level metrics read once per font file (upem, ascent/descent,
  OS/2 typo metrics, cap/x height, ideographic em box incl.
  declared-vs-fallback, vertical metrics) — exactly the designcraft#84
  surface.
- A missing-font diagnostic list and a name-cache API with explicit
  invalidation ("until fonts are added or rescanned", vectorcraft#1820).
- Per craftrules never-crash: lookups return diagnostics, never panic.

## What stays in each app

- Fallback/substitution policy and script-aware family choice — covered
  by the separate
  [craft-text-shaping proposal](https://github.com/ahmedhosnypro/craft-libs/pull/4);
  pdfcraft#1622 (std-14 substitution) is PDF-embedding domain and
  app-named-crate churn, explicitly **not** part of this hoist.
- App-side rendering, shaping engines and font binaries. No font
  binaries move (scope policy).
- UI presentation of missing fonts (e.g. deckcraft's toast) stays
  app-side; the crate exposes the diagnostic data.

## Architecture compliance

Per the target's AGENTS.md: a new crate under `crates/fontdb` named
`craft-fontdb`, inheriting workspace package fields and lints, useful
to more than one app (three demonstrated across windows), depending on
no app. No universal renderer — the crate enumerates and measures
fonts; rendering and shaping stay app-side. No i18n extraction — no
locale catalogs move. No font binaries — files are read from the OS,
none are bundled. Gate commands before any future merge: `cargo fmt
--check`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo test --workspace`. storytold/* repos were read via the GitHub
API only; all writes in this PR are on this fork.
