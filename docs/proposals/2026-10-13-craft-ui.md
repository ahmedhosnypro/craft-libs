# Proposal: craft-ui — shared numeric-field and slider-rail widget fixes

- **Date:** 2026-10-13 (window 15:53–22:53 UTC)
- **Target crate:** `craft-ui` (existing crate at `crates/ui`; name follows the
  repo's `craft-<name>` convention)
- **Status:** proposal only — no code extraction in this phase. The evidence
  carries the case; humans decide adoption.
- **Dedupe:** no open proposal PR on this repo covers `craft-ui` widget
  behaviour (open PRs #1–#8 cover adopt-sync, craft-gradient,
  craft-text-shaping, craft-mcp-server, craft-engine/gpu/image-algorithms, and
  craft-psd / craft-codecs-metadata / craft-graphcut). The
  [shared UI component audit](https://github.com/ahmedhosnypro/craft-libs/blob/main/docs/ui-components-audit.md)
  already flags numeric fields and slider/theme styling as surfaces where the
  twelve apps' widget behaviour "evolved differently".

## What this window saw

Two vectorcraft merges in the window are pure widget-behaviour fixes inside the
app's `ui-egui` crate: they change no app model, no commands, no i18n keys, and
no canvas interaction — they fix controls every Craft App draws.

### 1. Numeric fields lose typed input on click-away

- **Merge:** [storytold/vectorcraft#1787](https://github.com/storytold/vectorcraft/pull/1787)
  "Fix numeric fields reverting a typed value when clicking away instead of
  pressing Enter (#1637)", author MarekSpodBiedry, merged 2026-10-13T20:53:09Z.
- **Files:** `crates/ui-egui/src/widgets.rs` (+20/−2),
  `crates/ui-egui/src/tests_numfields.rs` (+70/−0).
- **Root cause (from the diff):** `recessed_text` read the typed text only while
  the field had focus at the start of its own drawing. When focus ended on a
  frame where the field itself did not draw with focus (a field drawn earlier
  takes it, or the canvas ends text input), `lost_focus` was reported but the
  typed text was discarded — the field reverted to the shown value.
- **Fix (from the diff):** a `had-focus` temp flag remembers focus across the
  frame boundary; a pointer-press outside the field surrenders focus before the
  press acts, so the typed value is committed first; Escape drops the edit. The
  patch ships 70 lines of widget-level regression tests (`tests_numfields.rs`).

### 2. Slider rails invisible on the default theme

- **Merge:** [storytold/vectorcraft#1808](https://github.com/storytold/vectorcraft/pull/1808)
  "Fix #1662: slider rails show on Medium Dark", author AyberkA0, merged
  2026-10-13T21:27:04Z.
- **Files:** `crates/ui-egui/src/theme.rs` (+11/−0),
  `crates/ui-egui/src/widgets.rs` (+3/−1).
- **Root cause (from the diff):** `widgets::slider` drew its rail in
  `input_border`, which on Medium Dark is `#5f5f5f` on a `#535353` panel — the
  rail all but vanishes. This affects the UI Scaling slider in Preferences and
  every other slider built on the widget.
- **Fix (from the diff):** the rail moves to `button_border` (button-outline
  colour), which contrasts with the panel in all four brightnesses; the filled
  part stays the accent colour. The patch adds
  `theme::tests::slider_rails_show_on_every_panel`, which checks the rail
  against the panel in all four brightnesses.

## Why this is a hoist, not app churn

Both diffs live entirely in the app's widget/theme layer, read like fixes any
other Craft App would want (the audit doc names numeric fields as a known
divergent surface; every app has sliders and number fields), and carry their
own tests with no app vocabulary. The pdfcraft parallel makes the need
concrete: pdfcraft pins `craft-ui` and maintains its own copy of this layer
(`crates/ui-egui/src/print_ui.rs` and its tests), so each app currently
re-fixes such bugs independently — or ships them unfixed.

## Extraction shape (for the humans who decide)

- Boundary: `craft-ui` keeps accepting small style values and returning
  interactions — per the audit's rule that themes, layout, localization and
  command handling stay in each app. `recessed_text` becomes a shared
  widget taking the tokens, id, text, width and row height; the slider rail
  colour becomes a token-resolved style value with the contrast test shared.
- Provenance (NOTICE draft): the code originates from
  [storytold/vectorcraft](https://github.com/storytold/vectorcraft)
  (`crates/ui-egui/src/widgets.rs`, `crates/ui-egui/src/theme.rs`), © 2026 the
  VectorCraft contributors, and enters craft-libs under the repo's MIT OR
  Apache-2.0 licensing with attribution recorded in `ATTRIBUTION.md` /
  `NOTICE`, consistent with the existing `crates/cms` provenance entries.
- Adoption path: extract behind the current `craft-ui` API surface first, bump
  the nine apps' `craft-ui` pins (see
  [adopt-sync](https://github.com/ahmedhosnypro/craft-libs/blob/main/docs/adopt-sync.md)
  — pins are currently 55–76 commits behind), then delete each app's local copy.

## Architecture compliance

Per [AGENTS.md](https://github.com/ahmedhosnypro/craft-libs/blob/main/AGENTS.md):
the proposed additions stay inside the existing `craft-ui` crate (no new crate
naming decision), are useful to more than one app (numeric fields and sliders
exist in all twelve), and depend on no app. No universal renderer is proposed:
themes, localization, layout and document semantics remain per-app, as the
scope policy requires.
