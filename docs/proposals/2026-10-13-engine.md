## Summary

Two PhotoCraft merges inside the shared-crate watch-paths landed generic,
app-agnostic hardening of the edit-command transaction core: fallible allocation
propagation through surface reads/writes and staged command edits, so a failed
operation preserves pixels, history, and retry-ability. This is exactly the
behavior craftrules' `standards/never-crash.md` mandates suite-wide, and it is
implemented app-side because no shared crate carries it.

## Evidence

- storytold/photocraft#4593 — "Preserve the document when Fade cannot allocate
  pixel buffers" (vbasky, merged 2026-10-13T16:46:11Z). 2 files, +28/−7:
  `crates/engine/src/edit_menu_cmds.rs`, `crates/engine/src/edit_menu_cmds/tests.rs`.
  Fade returns allocation errors through `fade_surface` and the staged command
  edit; failure preserves pixels, history and the retry path (tests at 8/16/32-bit).
- storytold/photocraft#4589 — "Report allocation failures when clearing a color
  channel" (vbasky, merged 2026-10-13T16:45:50Z). 2 files, +20/−3:
  `crates/engine/src/channel_cmds.rs`, `crates/engine/src/channel_clip/tests.rs`.
  Clear and Cut's destructive half move to fallible reads/writes so failure
  returns an error without committing pixels or a history state.

## Why this is generic, not app-domain

Both diffs are allocation-failure plumbing in the command-transaction layer:
fallible reads/writes, error returns, staged edits, history preservation. Nothing
in them names pixels-as-PhotoCraft-domain: any Craft App with an undo stack
(deckcraft, filmcraft, vectorcraft) needs the identical never-crash semantics
when an allocation fails mid-command. This matches the repo-list "hoist"
criterion: a fix another Craft App would also want.

## Proposed extraction (for human decision)

A `craft-engine` crate carrying the shared transaction core:

- fallible surface read/write traits with allocation-error propagation;
- staged command edit primitives (prepare → apply → commit) with
  preserve-on-failure semantics;
- history/undo integration boundary (app models stay app-side).
